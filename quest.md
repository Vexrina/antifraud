# Курсовая работа

В этом разделе описаны общие положения о правилах сдачи курсовых проектах и рекомендации к выполнению.

## Цель

Курсовая работа направлена на систематизацию, закрепление и расширение теоритических знаний
и практических навыков студента по пройденой диcциплине.

## Выбор темы

Студент выбирает одну из предложенных тем, наиболее подходящую для себя

- [Антифрод в банковских транзакциях](antifraud/README.md)
- [Clickstream-аналитика](clickstream/README.md)
- [Система сбора логов](logging/README.md)

> 🎁 Каждая тема предполагает работу с аналитикой, поэтому зачет пойдет и в курс по аналитике!

## Стек технологий

В рамках курсовой работы можно использовать лишь Docker
для развертывания компонентов проекта без Kubernetes и прочих DevOps-практик.

Допускается использовать любой подходящий стек, любой фреймворк или инструмент для выполения курсовой работы по соответсвующей теме.

Главное - чтобы вы разбирались в инструментах, которые используете и знали об их нюансах работы.

## Формат сдачи

### 1. Репозиторий на Github

Создайте репозиторий на Github, в котором будет вся реализация курсового проекта.

> Допускается использовать **монорепозиторий** для упрощения запуска и сдачи проекта

### 2. Pull Request

PR должен содержать **полностью рабочий проект** со всем необходимым окружением для запуска.

#### PR должен включать

- Исходный код
- Модульные и интеграционные тесты
- `README.md` - файл с обзором проекта и гайдом по запуску (см. [шаблон](./README.example.md))
- Отчет о покрытии исходного кода тестами
- Тестовые данные для загрузки в базы данных (либо ссылки для скачивания)
- UML-схемы, диаграммы, блок-схемы и пр., описывающие алгоритмы, разработанные в проекте для решения поставленной задачи
- DBML, отражающие схему в базах данных
- Airflow DAG
- Экспорт дашбордов (Grafana, Superset)

### 3. Защита

#### Введение

В течение 5-10 минут расскажите про свой проект.

Предоставьте все разрабатанные схемы и диаграммы, отражающие архитектуру вашей системы.
Опишите принцип работы разработанных алгоритмов для реализации требований.

#### Демонстрация

Продемонстрируйте работу вашей системы с разными источниками

#### Отказоустойчивость

На защите необходимо продемонстрировать, что система продолжает работать при отказе одного из компонентов
(например, ручная остановка контейнера шарда БД или реплики брокера).

#### Заключение

Резюмируйте итоги вашей работы и ответьте на вопросы преподавателя.

## Разбаловка

| Критерий | Баллы |
|----------|-------|
| Проект запускается | 3 |
| Проект соответствует бизнес-требованиям | 5 |
| Проект отказоусточив | 2 |
| Настроен мониторинг | 3 |
| README по шаблону | 3 |
| Покрытие тестами от 60% | 2 |
| Postman с примерами запросов | 2 |
| Чистый код (документирован, читаем и очевиден) | 2 |
| Защита (демо + ответы на вопросы) | 3 |
| 🎯 **Итого** | **25** |

> В таблице отражено максимальное кол-во баллов по критериям,
> но преподаватель вправе добавлять/убавлять баллы по каждому критерию на свое усмотрение.

## Рекомендации

> **Главное**: сделать работающий прототип, который можно объяснить и продемонстрировать.
Не пытайтесь сделать production-ready систему. Это курсовая, а не диплом!

- **Сначала проектируйте**, прорабатывайте схемы, исследуйте и только **после этого пишите код**!
- **Документируйте** исходный код, соблюдая стандарты, например:
  - [Javadoc](https://docs.oracle.com/en/java/javase/17/docs/specs/javadoc/doc-comment-spec.html)
  - [PEP8](https://peps.python.org/pep-0008/)
  - [Go doc](https://go.dev/doc/comment)
  - [PHPDoc](https://github.com/php-fig/fig-standards/blob/master/proposed/phpdoc.md)
  - [JSDoc](https://jsdoc.app/)
- Собюдайте [конвенцию коммитов](https://www.conventionalcommits.org/ru/v1.0.0-beta.2/)
- Каждый коммит - рабочая и протестированная версия проекта. Это облегчит поиск последней рабочей версии при поиске ошибки
- Пишите документацию на [Markdown](https://www.markdownguide.org/) в [Obsidian](https://obsidian.md/) или в вашей IDE.
- Используйте [Makefile](https://makefiletutorial.com/) для удобного взаимодействия с проектом
- Используйте [PlantUML](https://plantuml.com/ru/) для создания блок-схемы и диаграмм.
Есть возможность предпросмотра в IDE
(в VSCode через [расширение PlantUML](https://marketplace.visualstudio.com/items?itemName=jebbs.plantuml))
и утилиты graphviz и Java, установленных на вашем компьютере ([подробнее](https://plantuml.com/ru-dark/faq-install))
- Схемы БД реализуйте через [DBML](https://dbml.dbdiagram.io/home/)
и [dbdiagram.io](https://dbdiagram.io/home).
В VSCode есть [расширение](https://marketplace.visualstudio.com/items?itemName=dbdiagram.dbdiagram-vscode) для предпросмотра
- В PR предоставьте коллекцию [Postman](https://www.postman.com/)
или [Insomnia]([Insomnia](https://insomnia.rest/)) c примерами запросов и ответов для **каждого эндпоинта**.
Можно развернуть [Swagger](https://swagger.io/), но не обязательно.
- Используйте публичные **датасеты** с тестовыми данными,
например, из [Kaggle](https://www.kaggle.com/) или генерируйте свои на Python, Go или любом другом ЯП.
